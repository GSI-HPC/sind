You run a Slurm site and want to try a scheduler setting, or the next Slurm release, before production gets it. This episode puts the setting in the `slurm` section of a cluster config, shows where it lands in the generated `slurm.conf`, and runs the cluster on the Slurm release line production uses, through the official images.

## In this episode

- The `slurm` section and its map form, one fragment file per name: [Cluster Configuration]({{< relref "/configuration/cluster-config#slurm-section" >}})
- Where `main` lands in the generated `slurm.conf`, and which parameters it can replace: [Slurm Configuration]({{< relref "/architecture/slurm-config#slurmconf" >}})
- One official image per Slurm release line, and how to pick one with `defaults.image`: [Building Images]({{< relref "/container-images/building-images#official-images" >}})
- Watching `sind create cluster` work with `-vv`: [Diagnostics]({{< relref "/usage/diagnostics#verbose-logging" >}})
- How sind discovers the Slurm version, and why added workers must match it: [Slurm Configuration]({{< relref "/architecture/slurm-config#version-discovery" >}}) and [Worker Management]({{< relref "/usage/worker-management#image-and-slurm-version" >}})

## Commands

The files, config and commands from the video, in order, copied from the reference pages. The refresher shows the `slurm.conf` that sind generates for `sind create cluster dev`, from [Slurm Configuration]({{< relref "/architecture/slurm-config#slurmconf" >}}):

```text
# Generated by sind
ClusterName=dev
SlurmctldHost=controller
SlurmUser=slurm
StateSaveLocation=/var/spool/slurmctld
SlurmdSpoolDir=/var/spool/slurmd
PlugStackConfig=/etc/slurm/plugstack.conf

ProctrackType=proctrack/cgroup
TaskPlugin=task/cgroup
MpiDefault=pmix
ReturnToService=2
DefMemPerCPU=512

include /etc/slurm/sind-nodes.conf
```

and the `sind-nodes.conf` it includes, for three workers with `cpus: 2` and `memory: 1g`, from [Slurm Configuration]({{< relref "/architecture/slurm-config#sind-nodesconf" >}}):

```text
# Generated by sind
NodeName=worker-0 CPUs=2 RealMemory=1024 State=UNKNOWN
NodeName=worker-1 CPUs=2 RealMemory=1024 State=UNKNOWN
NodeName=worker-2 CPUs=2 RealMemory=1024 State=UNKNOWN
PartitionName=all Nodes=worker-0,worker-1,worker-2 Default=YES
```

The scheduler setting goes into the `slurm` section of `cluster.yaml`, here in map form, from [Cluster Configuration]({{< relref "/configuration/cluster-config#slurm-section" >}}):

```yaml
slurm:
  main:
    scheduling: |
      SchedulerType=sched/backfill
      SchedulerParameters=bf_continue
    resources: |
      SelectType=select/cons_tres
```

This creates `slurm.conf.d/scheduling.conf` and `slurm.conf.d/resources.conf`, and an `include` line for each in `slurm.conf`, before the `include` of `sind-nodes.conf`. The image of a release line goes into `defaults`, from [Building Images]({{< relref "/container-images/building-images#official-images" >}}):

```yaml
defaults:
  image: ghcr.io/gsi-hpc/sind-node:25.11
```

Create the cluster and watch it work, from [Diagnostics]({{< relref "/usage/diagnostics#verbose-logging" >}}):

```bash
sind -vv create cluster --config cluster.yaml
```

```bash

```
